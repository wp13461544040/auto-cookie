=== 修复 Node.js 18 兼容性问题 ===

【问题】
https-proxy-agent v9 和 socks-proxy-agent v10 要求 Node.js 20+
但服务器上是 Node.js 18

【解决方案】
降级依赖包到兼容 Node.js 18 的版本


【已修改文件】
1. backend/package.json
   - https-proxy-agent: 9.1.0 → 7.0.5
   - socks-proxy-agent: 10.1.0 → 8.0.4

2. backend/tsconfig.json
   - moduleResolution: node → node16
   - 添加 allowSyntheticDefaultImports: true

3. backend/src/routes/admin.ts
   - 使用 import 替代 require

4. backend/src/generator/cli.ts
   - 修复函数参数问题


【在本地 Windows 上传文件】

方法1：使用 SCP
scp backend\package.json root@服务器IP:/root/auto-cookie/backend/
scp backend\tsconfig.json root@服务器IP:/root/auto-cookie/backend/
scp backend\src\routes\admin.ts root@服务器IP:/root/auto-cookie/backend/src/routes/
scp backend\src\generator\cli.ts root@服务器IP:/root/auto-cookie/backend/src/generator/

方法2：使用脚本
bash sync-fix.sh root@服务器IP


【在服务器上重新安装和构建】

cd /root/auto-cookie/backend

# 清理旧依赖
rm -rf node_modules package-lock.json dist

# 重新安装（使用兼容版本）
npm install

# 验证版本
npm list https-proxy-agent
npm list socks-proxy-agent

# 编译
npm run build

# 检查编译结果（不应该有 require）
grep -n "require.*proxy-agent" dist/routes/admin.js

# 如果没有输出，说明修复成功
cd ..

# 重启服务
docker compose restart backend

# 查看日志
docker compose logs -f backend


【验证部署成功】

# 查看容器状态
docker compose ps

# 应该看到 backend 状态为 Up

# 访问服务
curl http://localhost:3000/health

# 应该返回 {"status":"healthy"}


【如果还有问题】

# 完全重建容器
cd /root/auto-cookie
docker compose down
docker compose up -d --build
sleep 20
docker compose exec backend npm run migrate
docker compose ps
